# Capital SP design system

Read `DESIGN.md` and the relevant files in `docs/design/` before changing interfaces. Treat the existing interface and approved references as the source of visual direction; preserve the distinct homepage and global token scopes. Reuse the native HTML, JavaScript components and CSS already in `src/` before introducing another implementation.

For public pages emphasize architectural composition, expressive geometry and legible property information; for administration prioritize clear forms, operational states and controlled density. Use photography only when rights and provenance are known. Keep decorative motion restrained, provide reduced-motion and keyboard alternatives, and preserve focus, labels and accessible feedback.

Check relevant desktop and mobile widths. When a browser is available, capture and inspect the changed area against the existing implementation or an approved reference. Run relevant tests; document visual decisions and any validation gaps in `docs/design/`.
